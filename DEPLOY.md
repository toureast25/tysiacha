# Деплой сервера комнат (PartyKit) и клиента (GitHub Pages)

Мультиплеер «Тысяча» работает на **PartyKit** (edge-сервер на Cloudflare Workers).
Сервер комнаты — единственный источник истины: он хранит состояние игры, применяет
редьюсер и рассылает снапшоты всем игрокам. Клиент — чистая статика на GitHub Pages.

## 0. Предварительно (без этого ничего не заработает)

1. Заведите аккаунт на https://cloudflare.com (бесплатного тарифа достаточно).
2. Установите Node.js 18+.
3. **Срочно:** старые креды HiveMQ (`[REDACTED-HIVEMQ-USER]` / `[REDACTED-HIVEMQ-PASS]`) уже попали в историю git
   публичного репозитория — отзовите/смените их в панели HiveMQ Cloud (Access
   Management). HiveMQ больше не используется, но креды считаются скомпрометированными.
4. Очистите историю git от секретов (`git filter-repo` или BFG) либо заведите новый
   репозиторий без «грязной» истории.

## 1. Установка зависимостей

```bash
npm install
```

`partykit` ставится как dev-зависимость (см. package.json).

## 2. Локальная разработка

В двух терминалах:

```bash
# Терминал 1 — сервер комнат (по умолчанию ws://localhost:1999)
npm run partykit:dev

# Терминал 2 — клиент (Vite, http://localhost:3000)
npm run dev
```

Для локальной разработки укажите клиенту адрес локального сервера. Создайте файл
`.env` в корне:

```
VITE_PARTYKIT_HOST=localhost:1999
```

(в `utils/config.js` `useTls` тогда лучше временно поставить `false`, либо используйте
`npm run partykit:dev` с TLS. Для быстрой проверки можно задать хост и через
переменную окружения при запуске vite.)

## 3. Деплой сервера комнат

```bash
# логин в Cloudflare (откроется браузер)
npx partykit login

# публикация сервера (конфиг — partykit.json: main = party/server.js)
npm run partykit:deploy
```

После деплоя PartyKit покажет публичный адрес вида:

```
tysiacha.<ваш-аккаунт>.partykit.dev
```

## 4. Подключение клиента к задеплоенному серверу

Задайте этот адрес для сборки клиента. Создайте/обновите `.env` в корне:

```
VITE_PARTYKIT_HOST=tysiacha.<ваш-аккаунт>.partykit.dev
```

Затем обычная сборка статики:

```bash
npm run build
```

Результат в `dist/` публикуется на GitHub Pages как и раньше (GitHub Actions /
ветка `gh-pages` — оставьте вашу текущую схему публикации).

## 5. Как это работает (кратко)

- Клиент открывает `wss://<host>/party/<КОД_КОМНАТЫ>` (см. `components/hooks/useRoom.js`).
- Вход: `{type:'HELLO', sessionId, playerName}`; действия: `{type:'INTENT', action, msgId}`.
- Сервер (`party/server.js`) применяет `gameReducer` и шлёт `{type:'SET_STATE', payload}` всем.
- Presence/heartbeat: клиент шлёт `PING`, сервер по таймеру помечает `away`/`offline`.
- Состояние персистится в `room.storage` — переживает перезапуск инстанса комнаты.
- «Хост» (`hostId`) остался только для админ-кнопок (старт/новая игра/кик/промоут);
  авторитет у сервера, split-brain невозможен (один инстанс на комнату).

## 6. Что НЕ протестировано end-to-end

Автотестов сети в репозитории нет. Перед боевым использованием проверьте вручную:

- создание комнаты и вход 2–5 игроков с разных устройств;
- бросок/откладывание/запись очков, смена хода, «бочки», штрафы, победа;
- реконнект: закрыть вкладку и открыть заново по ссылке `?room=КОД` — слот и очки
  должны сохраниться (тот же `sessionId` в `sessionStorage`);
- «мёртвый» игрок: закрыть вкладку — статус должен уйти в `away`, затем `offline`;
- кик и передача прав хоста;
- режим зрителя;
- локальная (hotseat) игра не должна ходить на сеть.

## 7. Заметки

- `partykit.json` — конфиг сервера (`main: party/server.js`). Меняйте `name`, если
  нужно имя комнаты-сервера отличное от `tysiacha`.
- Бесплатный тариф PartyKit/Cloudflare имеет лимиты (соединения/сутки, CPU). Для
  компании друзей более чем достаточно.
- После релиза клиента инкрементируйте `CACHE_NAME` в `sw.js`, чтобы игроки не сидели
  на старом кэше.
